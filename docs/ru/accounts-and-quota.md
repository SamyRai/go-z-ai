# Аккаунты и квоты

## Несколько аккаунтов

Вместо ручного редактирования `.env` при каждой смене ключа, один раз
зарегистрируйте именованные аккаунты и переключайтесь между ними:

```bash
go-z-ai accounts add personal --api-key sk-...          # type and region auto-detected
go-z-ai accounts add work --api-key sk-... --type coding_plan --region china

go-z-ai accounts list
go-z-ai accounts use personal        # sets the default for future commands
go-z-ai accounts show                # shows the active account
go-z-ai accounts remove work --yes
```

Аккаунты хранятся в `$XDG_CONFIG_HOME/zai-client/accounts.json` (или
`~/.config/zai-client/accounts.json`), запись выполняется атомарно с правами
`0600`. (Каталог намеренно называется `zai-client`, а не `go-z-ai`, чтобы у
существующих установок файл `accounts.json` сохранялся при обновлении с имени
до переименования.)

**Автоопределение типа и региона:** `accounts add` опрашивает
monitor/quota-эндпоинт, применимый только к coding plan, — бесплатный вызов без
расхода token: сначала на указанном вами `--region` (по умолчанию global), затем
на другом шлюзе, поскольку ключ, выпущенный в Китае, отвечает только на
`open.bigmodel.cn`. Корректно сформированный ответ с квотой означает
`coding_plan` в этом регионе. Если ни один шлюз не опознал подписку, но хотя бы
один ответил, ключ считается `pay_as_you_go` — это вывод методом исключения, а
не положительное подтверждение, поскольку ни один эндпоинт не специфичен для
ключей pay-as-you-go. Если ни один из шлюзов недоступен, `add` завершается
ошибкой, а не гадает. Передайте `--type`, чтобы пропустить опрос; тогда регион
берётся из `--region`. `go-z-ai account detect` выполняет тот же опрос для
текущего ключа, ничего не сохраняя.

**Порядок разрешения** — полный список приоритетов для `--api-key`,
`--account`, переменных окружения и активного сохранённого аккаунта см. в
разделе [Начало работы](getting-started.md#2-аутентификация).

## Проверка ключа

```bash
go-z-ai account detect          # type (coding plan / pay-as-you-go), region, plan tier — free
go-z-ai account status          # does the key work and can it spend right now?
go-z-ai account status --watch 5m
go-z-ai account balance         # pay-as-you-go wallet
go-z-ai account subscriptions   # GLM Coding Plan subscriptions
```

`account status` — бесплатная проверка квоты для ключа coding plan. У Z.AI нет
вызова баланса для ключей pay-as-you-go, поэтому для них отправляется одно
платное завершение на один token — а `--watch` повторяет его на каждом
интервале, так что делайте интервал длинным. `account balance` и
`account subscriptions` читают biz API, который Z.AI не документирует; они
**НЕ ВЕРИФИЦИРОВАНЫ ВЖИВУЮ** (см. [Дорожную карту](roadmap.md)). Балансы
указываются в расчётной валюте региона (USD на api.z.ai, CNY на
open.bigmodel.cn).

## Мониторинг квоты и использования

Квота GLM Coding Plan делится на окна, и то, какие из них есть у аккаунта,
зависит от поколения тарифа:

| Тариф | Окно | Метрики |
|---|---|---|
| На основе кредитов (продаётся с 2026-07-30) | 5-часовое, недельное (`CREDIT_LIMIT`) | Кредиты. Использование моделей и вызовы MCP-инструментов списываются с одних и тех же кредитов; Web Search, Web Reader и Zread стоят 1,2 кредита за вызов ([docs](https://docs.z.ai/devpack/overview)) |
| Устаревшие токенные тарифы | 5-часовое, недельное (`TOKENS_LIMIT`) | Token, сообщаются только в процентах |
| Устаревшие токенные тарифы | месячное (`TIME_LIMIT`) | Вызовы MCP-инструментов с разбивкой по инструментам |

5-часовое окно обновляется через пять часов после расхода; API сообщает время
сброса каждого окна. Считайте типы окон открытым множеством: клиент выводит
неизвестный тип в общем виде, а не падает.

```bash
go-z-ai accounts quota                    # across all stored accounts
go-z-ai accounts usage --days 14          # token/tool usage heat map
go-z-ai accounts usage --today            # shorthand for --days 1
go-z-ai usage quota                       # the current key only
go-z-ai account status [--watch 5m]       # can the key spend right now?
```

Пример вывода `usage quota` (`accounts quota` печатает то же самое по каждому
аккаунту):

```text
📊 GLM Coding Plan (pro)

• 5-hour credit window — 62% used
  620 / 1.0K used — 380 left
  resets Oct 12 11:14 CEST (in 2h 14m)
  62% used at 55% of window elapsed — on pace to run out ~32m before reset
  ⚡ peak hours until 12:00 CEST: credits bill at the full rate (off-peak costs 50%)

• weekly credit window — 41% used
  4.1K / 10.0K used — 5.9K left
  resets Oct 18 07:00 CEST (in 5d)
  41% used at 15% of window elapsed — on pace to run out ~4d before reset
  ⚡ peak hours until 12:00 CEST: credits bill at the full rate (off-peak costs 50%)
```

Строка **pace** отвечает на вопрос «тратим ли слишком быстро?» — она
экстраполирует *собственное* сообщённое окном использование на долю истекшего
времени окна, так что вы узнаёте о риске преждевременного исчерпания *до того*,
как упрётесь в стену. Это линейная математика по числам, возвращаемым API.

### Пиковые часы

Пиковые часы — с понедельника по пятницу, 14:00–18:00 UTC+8, для всех
пользователей, независимо от их часового пояса ([docs](https://docs.z.ai/devpack/overview)).
API квоты применяет пиковую тарификацию, не раскрывая её, поэтому CLI и TUI
добавляют уведомление, пока действуют пиковые часы. Во что обходится пик,
зависит от тарифа:

- **Тарифы на основе кредитов** списывают пиковое использование по стандартной
  ставке кредитов, а внепиковое — по 50%.
- **Устаревшие токенные тарифы** считают GLM-5.3 с коэффициентом 3× в пик (1× вне
  пика), а GLM-5.3-Flash — 1,2× (0,4× вне пика).

Объявленные акции тарифицируют каждый час по внепиковой ставке; текущая идёт с
2026-09-25 по 2026-10-07 (UTC+8). Эти правила находятся в
`internal/usageview/peak.go`, по состоянию на 2026-10-02.

### Часовые пояса

Все времена отображаются в **вашем локальном часовом поясе**. Времена сброса —
абсолютные метки времени, поэтому конвертация им не нужна. Эндпоинты
использования, однако, обмениваются строками времени без указания пояса по
настенным часам самого сервера, **UTC+8**, поэтому **тепловая карта
использования** (`accounts usage`) переводит свои окна и интервалы корзин в ваше
локальное время и добавляет однострочное примечание с названием пояса сервера,
если он отличается. Запрашиваемый диапазон также формируется в поясе сервера
перед отправкой, так что `--today` получает *ваш* сегодняшний день, а не срез,
сдвинутый на разницу поясов.

Если живой захват когда-либо покажет для вашего аккаунта другой пояс сервера,
переопределите это допущение через `--monitor-timezone` или
`ZAI_MONITOR_TIMEZONE` (принимает названия IANA вроде `Asia/Shanghai`, `UTC`
или смещения вроде `+8`).

Не каждый аккаунт отображает все окна — на то, какие окна применимы, влияют и
уровень тарифа, и тип аккаунта (`accounts show <name>` сообщает тип аккаунта;
аккаунты `pay_as_you_go` полностью пропускаются командами `accounts quota` /
`accounts usage`, поскольку coding-plan monitor-эндпоинт к ним неприменим).

### Почему утверждение «использование не существует» неверно

Если вы встретите старые заметки в интернете (или в истории git этого репозитория),
утверждающие, что у Z.AI нет API использования/квоты — это было справедливо
только для общей поверхности `/api/paas/v4`, проверенной изолированно.
Monitor-эндпоинты coding plan (`/monitor/usage/quota/limit`,
`/monitor/usage/model-usage`, `/monitor/usage/tool-usage`) реальны — именно их
вызывает собственный плагин использования Z.AI — и именно на них построен
`QuotaService` из `pkg/client`. Если `accounts quota` ничего не возвращает для
аккаунта, сначала проверьте его тип (у аккаунтов `pay_as_you_go` действительно
нет этих данных), прежде чем предполагать, что API сломан.

## Региональные шлюзы (api.z.ai / open.bigmodel.cn)

Z.AI обслуживает одно и то же семейство моделей GLM с двух региональных
шлюзов: международный хост `api.z.ai` (по умолчанию) и материковый китайский
зеркальный `open.bigmodel.cn`. То, на какой хост попадёт конкретный вызов,
решают два независимых фактора:

**1. Embeddings и Moderations всегда маршрутизируются на
`open.bigmodel.cn`** — это единственные сервисы, привязанные к китайскому хосту
в коде (`pkg/client/embeddings.go` и `pkg/client/moderations.go` оба
нацелены на `BigModelBaseURL`). `--china-api-key` /
`ZAI_CHINA_API_KEY` — переключатель учётных данных здесь; он опционален,
поскольку обычный `ZAI_API_KEY` аутентифицируется одинаково на обеих
платформах (тот же каталог `/models`, те же ошибки биллинг-уровня — живая
верификация), поэтому откат к общему ключу — частый случай. Задайте отдельный
китайский ключ, только если у вас есть отдельные учётные данные, применимые
исключительно на bigmodel.cn. Rerank и Voice используют `--base-url` по
умолчанию (`api.z.ai` по умолчанию) — они задокументированы только на китайской
платформе, но клиент не принудительно маршрутизирует их.

**2. Всё остальное следует за `--region china` (или `ZAI_REGION=china`)**:
чат, Anthropic и Responses API, квота/использование, аккаунт (баланс,
подписки), агенты и определение типа аккаунта переходят на `open.bigmodel.cn`;
в противном случае они используют `api.z.ai`. Именно этот переключатель нужен
ключу, выпущенному в Китае, — без него эти вызовы уходят на `api.z.ai`, где такой
ключ может провалить аутентификацию или быть неверно классифицированным.
Сохранённый аккаунт запоминает свой регион, поэтому `accounts use` переключает и
его. `--base-url` по-прежнему переопределяет только корень chat/PaaS (для
аккаунта Coding Plan это coding-корень тарифа), а хост Embeddings/Moderations
никогда не меняется. Псевдонимы: `cn`, `bigmodel`, `west`; неизвестное значение
откатывается к global.

То, получите ли вы реальные результаты от китайских задокументированных сервисов
(Embeddings, Moderations, Rerank, Voice), зависит от **тарифа аккаунта**, а не
от того, какой ключ вы используете. Каталог моделей аккаунта GLM Coding Plan
содержит только чат — вызов этих сервисов с таким аккаунтом возвращает
`400 Unknown Model` (код ошибки 1211) на любой из платформ. Это ожидаемое
поведение, а не баг: проверьте `go-z-ai models list`, чтобы увидеть, что
реально входит в каталог вашего аккаунта.

Хосты китайского зеркала для monitor/biz/agents/detection повторяют структуру
путей `api.z.ai`, но здесь **НЕ ВЕРИФИЦИРОВАНЫ ВЖИВУЮ** — для
`open.bigmodel.cn` живая верификация подтвердила ту же поверхность OpenAPI для
`/models` и `/chat/completions`, но пути monitor/biz/agents на китайской
стороне ещё не были зафиксированы в cassette. См. [Дорожную карту](roadmap.md).

## Коды ошибок

`APIError` (см. [Обработка ошибок](error-handling.md)) категоризирует каждый
код ошибки Z.AI, известный клиенту. Те, с которыми вы чаще всего столкнётесь в
контексте квоты:

| Код | Значение | Повторяемая |
|---|---|---|
| 1113 | Недостаточный баланс / нет пакета ресурсов | Нет — пополните счёт или смените аккаунт |
| 1308 | Достигнут лимит использования для текущего окна | Нет — дождитесь сброса |
| 1316 / 1317 | 5-часовое / 7-дневное окно исчерпано и нет баланса для дополнительного использования | Нет — дождитесь сброса или пополните счёт |
| 1211 | Неизвестная модель | Нет — обычно ограничение по тарифу, см. выше |
| 1302 | Достигнуто ограничение скорости | Да — клиент уже повторяет с backoff |

Полная таблица и способы ветвления по `APIError.Category` в собственном коде —
в разделе [Обработка ошибок](error-handling.md).
