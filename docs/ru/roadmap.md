# Дорожная карта и ограничения

Что ещё открыто, почему, и какое именно действие закрывает пункт. Пункты
покидают эту страницу, когда зафиксированная cassette или принятое изменение
их закрывает — это рабочий список соглашения «сначала проверь» (почему — см.
[Участие в проекте § соглашение о живой верификации](../../CONTRIBUTING.md) и
[Архитектура § соглашение о живой верификации](architecture.md#соглашение-о-живой-верификации)).

Каталог моделей, формы API и поведение Coding Plan в последний раз обновлялись
2026-10-02. `docs.z.ai` не удалось получить напрямую в ходе того исследования,
поэтому эти факты взяты из сводок результатов поиска по официальной
документации, официальных SDK и npm-пакета и (где отмечено) сторонних
источников — именно поэтому ряд пунктов ниже указан как не верифицированный, а
не подтверждённый.

> **Запись cassette самостоятельно:** у каждого пункта ниже, называющего тест
> `TestVerify*`, есть такой тест, который SKIP-ается, пока вы не захватите
> cassette пути успеха через `ZAI_RECORD=1`. Перед сохранением харнесс
> редуцирует `Authorization` до `Bearer REDACTED` — перед коммитом проверьте
> через `grep "Bearer " pkg/client/testdata/cassettes/<name>.yaml`.
>
> ```sh
> ZAI_RECORD=1 ZAI_API_KEY=<real-key> go test -run TestVerify<Name> ./pkg/client
> ```

## Не верифицировано на живую

Три группы: **сервисы**, для которых форма успешного ответа ещё не
зафиксирована, **поля chat API**, которые соответствуют документации, но не
закреплены cassette, и **данные-снимки**, требующие периодического обновления.

### Сервисы, требующие cassette пути успеха

У используемого до сих пор dev-аккаунта нет PAYG-баланса / прав для этих
сервисов, поэтому подтверждены только форма запроса и пути ошибок. Cassette,
зафиксировавшая реальный успешный ответ, закрывает каждый пункт.

- **Эндпоинты аккаунта (biz)** — `AccountService.Balance`
  (`GET /api/biz/account/query-customer-account-report`) и
  `AccountService.Subscriptions` (`GET /api/biz/subscription/list`). Z.AI не
  документирует biz API; маршруты и имена полей взяты из собственного клиента
  ZCode от Z.AI и общественных инструментов учёта использования, и оба
  декодируются через общий `Envelope[T]`. НЕ ВЕРИФИЦИРОВАНО НА ЖИВУЮ, ни в
  одном из регионов; чтобы закрыть вопрос, запишите `TestVerifyAccountBalance` и
  `TestVerifyAccountSubscriptions`.
- **Embeddings, Moderations и Rerank на `api.z.ai`**
  (`TestVerifyEmbeddings`, `TestVerifyModerations`) — не подтверждено, работают
  ли они вообще на международной платформе. Embeddings и Moderations
  маршрутизируются на `open.bigmodel.cn` (`BigModelBaseURL`); Rerank
  использует `Config.BaseURL`. Каждый проверенный аккаунт вернул
  `400 Unknown Model` (код 1211) для опробованных ID моделей (embeddings и
  moderations на обоих хостах, rerank на `api.z.ai`); это похоже на
  ограничение по тарифу, а не на баг маршрутизации (см.
  [Аккаунты и квоты](accounts-and-quota.md)), но формы успешных ответов не
  видны. Для Rerank пока нет теста `TestVerify*`; `TestRerankCreateLive` лишь
  воспроизводит 1211.
- **Anthropic Messages** (`TestVerifyAnthropicMessages`) — маршрутизация,
  заголовок `anthropic-version` и Bearer-аутентификация подтверждены (бракованный
  ключ возвращает чистый 401, а не 404/timeout). Открытый вопрос, который
  закрыла бы cassette: GLM отдаёт рассуждения как Anthropic-блоки `thinking`
  или как OpenAI-поле `reasoning_content`? `AnthropicResponse.Thinking()`
  читает оба. ([claude-code-router#1133](https://github.com/musistudio/claude-code-router/issues/1133))
- **Успешная форма ответа Agents `Invoke`** (`TestVerifyAgentsInvoke`) — на
  живую сегодня подтверждён только конверт ошибки
  (`ID`/`AgentID`/`Status`/`Error`), через `testdata/cassettes/agents_invoke.yaml`
  (200 со встроенной ошибкой). Форма успешного ответа `Choices`/`Usage`
  смоделирована только по документации, как и формы ответов `async-result`
  за пределами его конверта ошибки (`agents_async_result.yaml`) и форма
  контента для агентов изображений/видео.
- **Voice `Clone` / `Delete`** (`TestVerifyVoiceClone`, `TestVerifyVoiceDelete`)
  — `Voice List` подтверждён на живую; для clone/delete требуется загруженный
  образец аудио и реальный ID клонированного голоса для записи. Для clone
  нужны `ZAI_VOICE_SAMPLE_FILE_ID` + `ZAI_VOICE_NAME`; для delete —
  `ZAI_VOICE_ID`.
- **Эндпоинты квоты и использования (monitor)** (`TestVerifyQuotaLimit`,
  `TestVerifyQuotaLimitChina`) — пока ни одна зафиксированная cassette их не
  покрывает. Форма тарифа на основе кредитов (окна `CREDIT_LIMIT`,
  `QuotaTypeCreditLimit`) смоделирована по сторонним образцам monitor API, а
  допущение `MonitorServerTZ` (UTC+8) для строк времени без пояса проверялось
  только на глобальном хосте.
- **Responses API** (`TestVerifyResponses`) — `ResponsesService` следует
  спецификации Responses от OpenAI; Z.AI документирует эндпоинт (для Codex), но
  не его schema. Запись подтвердила бы формы элементов и событий, какие
  события рассуждений выдаёт GLM (`response.reasoning_text.delta` или
  `response.reasoning_summary_text.delta`) и принимаются ли ключи
  pay-as-you-go или только ключи Coding Plan.
- **Эндпоинты Batch и Files в целом** — специализированного каркаса
  `TestVerify*` ещё нет; для записи потребовался бы аккаунт PAYG с
  соответствующими правами.

### Поля chat API, ожидающие cassette

Эти поля добавлены в `pkg/client/chat_types.go` / `chat.go`, чтобы соответствовать
актуальной спецификации завершения чата docs.z.ai и официальным SDK. Они
аддитивны и покрыты unit-тестами, но НЕ ВЕРИФИЦИРОВАНЫ НА ЖИВУЮ, пока cassette
не зафиксирует точную wire-форму.

- **`ChatRequest.ToolStream`** (`TestVerifyChatStreamToolCall`) — стримаемые
  дельты tool-call для GLM-4.6+. Cassette должна показать, что дельты
  tool-call приходят в нескольких SSE-чанках через `StreamDelta.ToolCalls`.
- **Дискриминация `Tool` между `function` / `retrieval` / `web_search` / `mcp`**
  (`NewFunctionTool` / `NewRetrievalTool` / `NewWebSearchTool` / `NewMCPTool`)
  — спецификация перечисляет все четыре типа; подтверждён только `function`.
  Форма payload `web_search` следует официальной документации и примерам SDK, а
  инструмент `mcp` и его записи ответа `MCPCall` смоделированы только по
  документации.
- **`ChatResponse.WebSearch`** (`TestVerifyChatWebSearchResponse`) —
  массив `web_search` верхнего уровня, возвращаемый при срабатывании
  инструмента `web_search`. Форма записи переиспользует `WebSearchResult`
  из `tools.go` (верифицировано на живую для отдельного инструмента
  web-search); размещение как массива верхнего уровня смоделировано по
  документации.
- **`ChatRequest.ReasoningEffort`** — проверяется локально по записи модели в
  каталоге (`ReasoningEfforts`; семейство GLM-5.3 принимает
  `low`/`high`/`max`, GLM-5.2 — каждый уровень). Правила по моделям и реакция
  сервера на неподдерживаемый уровень взяты из документации и SDK; ни одна
  cassette их не закрепляет.
- **Preserved thinking** — `ThinkingConfig.ClearThinking` и возврат
  `Message.ReasoningContent` в последующих ходах (что `RunWithTools` делает
  автоматически) следуют документированному контракту; поведение сервера,
  когда рассуждения опущены или изменены, не зафиксировано.
- **Вход видео и файлов** — `Message.Videos` / `Message.Files` кодируются как
  части контента `video_url` / `file_url` для нативно мультимодальных моделей
  (`DefaultVisionModel`); кодирование следует документации, и cassette для него
  нет.
- **Константы `FinishReason*`** (`sensitive`, `model_context_window_exceeded`,
  `network_error`) — добавлены из документации; ни одна cassette пока не
  воспроизводит эти пути завершения.
- **Клиентская regex для имён инструментов** (`^[A-Za-z0-9_-]{1,64}$`) и
  **ограничение в 128 функций** — задокументированные серверные правила,
  которые мы применяем локально; не подтверждено, что они являются точным
  критерием отказа на стороне сервера.
- **Китайский региональный шлюз для monitor/biz/agents/Anthropic/detection** —
  `RegionChina` направляет их на `open.bigmodel.cn`. `/models` и
  `/chat/completions` верифицированы на живую на китайском хосте; остальные
  пути смоделированы зеркалированием структуры `api.z.ai` (`Region` в
  `region.go`) и требуют cassette с подходящим китайским ключом для
  подтверждения.

### Данные-снимки, требующие периодического обновления

- **Каталог моделей** (`pkg/client/models_catalog.go`) — ID, размеры контекста,
  лимиты вывода, цены, возможности и уровни reasoning effort — это снимок,
  перенесённый 2026-10-02 со страниц цен и моделей docs.z.ai (через сводки
  поиска; часть строк опирается на сторонние источники, а статус
  `glm-5-turbo` / `glm-5v-turbo` неопределён). API не подаёт сигнала, когда
  что-либо из этого меняется. В заголовке файла перечислены шаги обновления.
- **Пиковые часы и внепиковая акция** (`internal/usageview/peak.go`) — пиковое
  окно по будням 14:00-18:00 UTC+8 и множители тарификации продублированы на
  стороне клиента, потому что API квоты их не раскрывает, а запись
  `offPeakPromotions` сейчас покрывает акцию, которая заканчивается
  2026-10-07. Удалите или обновите её, когда этот срок пройдёт.

### Более старые открытые вопросы (без специализированного теста пока)

- **Переписывание совместимости tool-schema** — набор конструкций JSON-Schema,
  которые парсер GLM отклоняет с HTTP 500
  (`anyOf`/`oneOf`/`allOf`/`$ref`), взят из общественных баг-репортов
  ([claude-code-router#1474](https://github.com/musistudio/claude-code-router/issues/1474)),
  а не воспроизведён здесь на живом аккаунте. Само переписывание полностью
  покрыто unit-тестами и инертно на уже плоских schema; cassette,
  зафиксировавшая, какие именно конструкции дают 500 (а какие проходят после
  уплощения вывода), повысила бы статус с «задокументированное поведение» до
  «верифицировано на живую». См. `pkg/client/toolschema.go`.

## Дальнейшие шаги

- **Запишите ожидающие верификационные cassette** — перечисленные выше тесты
  `TestVerify*` существуют и SKIP-аются, пока не записаны. Запустите их с
  реальным ключом (pay-as-you-go для баланса, Coding Plan для квоты, Responses
  и подписок и китайский ключ для `TestVerifyQuotaLimitChina`), например
  `ZAI_RECORD=1 ZAI_API_KEY=… go test -run 'TestVerify(AccountBalance|AccountSubscriptions|QuotaLimit|Responses)$' ./pkg/client -v`,
  затем исправьте любые имена полей, которым реальные ответы противоречат.
  Хук записи редуцирует ключ и идентификаторы аккаунта; перед коммитом
  проверьте YAML.
- **Размещённые MCP-серверы для Codex** — `go-z-ai coding mcp add codex`
  предлагает только сервер Vision, пока не будет исправлен openai/codex#14793
  (Codex отвергает пустой ответ `notifications/initialized` от размещённых
  серверов Z.AI); после этого дайте `codex` форму записи удалённого MCP (`url`
  плюс `http_headers`).
- **Эндпоинт диалога агента** — не реализован. `POST /v1/agents/conversation`
  возвращает историю диалога агента, который ведёт диалоги (документация
  говорит, что он поддерживается только для `slides_glm_agent`).
  `AgentAsyncResultRequest` уже несёт `ConversationID`; самого вызова истории
  нет. Связанное: `AgentInvokeRequest.Stream` есть в wire-типе, но для агентов
  нет потокового декодера, так что потоковые ответы агентов не поддерживаются.

## Не реализовано

- **Производительные бенчмарки** — отложены до измерения реального узкого
  места; ни один известный горячий путь пока не оправдывает их проведения
  (профилируйте перед оптимизацией).

## Выпущено (оставлено для ориентира)

- **Хуки наблюдаемости запросов/ответов** — вошли в v0.2.0. Шов `Hook` в
  `pkg/client` (`OnRequest`/`OnResponse`/`OnError`/`OnStreamChunk`)
  срабатывает на каждое событие жизненного цикла запроса, с одним
  завершающим вызовом на попытку; первая конкретная реализация — `OTelHook` в
  `pkg/observe` (спаны и метрики OpenTelemetry). См.
  [Руководство по библиотеке → Хуки наблюдаемости](library-guide.md#хуки-наблюдаемости).

## Намеренно не реализовано

- **Assistant API** — подтверждён как устаревший / deprecated. Собственный
  живой OpenAPI-spec Z.AI (`docs.bigmodel.cn/openapi/openapi.json`) помечает
  каждый путь Assistant как `"deprecated": true`, а вызов его из `api.z.ai`
  полностью уходит в timeout вместо возврата ошибки. Создавать клиент для
  API, выводимого из эксплуатации, не стоит затрат на поддержку — если Z.AI
  когда-либо отменит это решение, в spec выше готовы полные schema
  запросов/ответов для транскрипции.
